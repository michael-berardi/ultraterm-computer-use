# Architecture Overview

This repository has been reduced from a template to a local UltraTerm Computer Use project. The main line is the macOS automation MCP server written in Swift. It is joined by experimental Windows and Linux runtimes. These are standalone Go binaries that expose the same set of 9 native Computer Use tools. The Codex plugin adds a persistent Node.js REPL on top of the native MCP server and exposes `js` / `js_reset` to the model.

## Current Directory Layout

- `apps/UltraTermComputerUse`
  Main entry point. It handles the CLI commands `mcp`, `doctor`, `list-apps`, `targets`, `tools`, `inspect`, `snapshot`, `call`, `preview`, `record`, `turn-ended`, and the global flags `-h` / `--help` / `-v` / `--version`. When started with no arguments, it checks permissions first. It opens the permission onboarding window in app mode (no Dock icon) only when a permission is missing. `doctor` opens the same onboarding UI only when a missing permission is detected.
- `apps/UltraTermComputerUseFixture`
  Local GUI fixture app that hosts low-risk, predictable click, typing, scroll and drag verification paths.
- `apps/UltraTermComputerUseSmokeSuite`
  End-to-end smoke runner. It starts the fixture and the MCP server and calls all 9 tools over JSON-RPC. It also supports a standalone visual cursor idle smoke test. This test uses a cross-process observation file to assert that, while waiting for the next move, the cursor stays anchored at its tip with a small rotation wobble instead of drifting sideways.
- `apps/UltraTermComputerUseWindows`
  Experimental Windows runtime. It does not depend on Swift or a `.app` bundle. The Go CLI/MCP entry point embeds a PowerShell UI Automation bridge. The build output is `ultraterm-computer-use.exe`, distributed as bundled artifacts in `dist/windows/<arch>/` of the existing npm package.
  PowerShell child processes use `CREATE_NO_WINDOW`, so an MCP host without a console does not flash a console window or steal focus on every call. stdout and stderr still use pipes. The Windows Go tests call the real launch path from a detached parent process and check the console handle, Unicode JSON and error output.
- `apps/UltraTermComputerUseLinux`
  Experimental Linux runtime. It does not depend on Swift or a `.app` bundle. The Go CLI/MCP entry point embeds a Python AT-SPI bridge. The build output is `ultraterm-computer-use`, distributed as bundled artifacts in `dist/linux/<arch>/` of the existing npm package.
- `packages/UltraTermComputerUseKit`
  Core library, containing:
  - MCP stdio transport and tool registry
  - app discovery
  - Accessibility / window snapshot
  - keyboard and mouse input simulation
  - software cursor overlay
  - fixture test bridge
  - screen capture for `preview` and `record` (`PreviewCapture.swift`, `RecordingCapture.swift`, `ScreenStreamCapture.swift`)
  - structured errors, exit statuses and tool-argument schema validation (`Errors.swift`, `ToolDefinitions.swift`)
- `scripts/`
  Repository-level automation commands. These include the smoke tests, the `.app` packaging entry point, the Windows `.exe` and Linux binary build entry points, the npm distribution scripts, the GitHub Release direct-download archive packaging, and the JS REPL adapter and npm CLI controller under `scripts/node-repl/`.
- `skills/`
  Installable skill for agent runtimes. The current `skills/ultraterm-computer-use/SKILL.md` is only a lightweight entry point and index. Details on installation, MCP/CLI usage and troubleshooting are split into adjacent `references/` files and loaded on demand. `scripts/package-skill.sh` validates and packages the `.zip` / `.skill` artifacts.
- `docs/`
  Analysis notes, plans, history and project constraints.

## Runtime Layers

### 1. App Mode Layer

- `UltraTermComputerUse` in default app mode launches `PermissionOnboardingApp`.
- The app bundle runs as an `LSUIElement` agent-style app. It does not keep a persistent Dock icon by default, but it can still show the permission window on demand.
- When a user runs the macOS `ultraterm-computer-use mcp`, `doctor`, `call`, `snapshot`, `inspect`, `targets` or `list-apps` from a terminal, the CLI first starts the hidden app agent of the same `.app` bundle through LaunchServices. It then forwards requests through a Unix domain socket in the user's temporary directory. The process that calls Accessibility, ScreenCaptureKit and the action tools is always `UltraTerm Computer Use.app`, not a terminal emulator or a Node launcher. The default socket file name is kept for backward compatibility. Embedding hosts can set `ULTRATERM_COMPUTER_USE_AGENT_SOCKET_NAMESPACE` to use a private socket derived from a namespace digest, which avoids sharing an agent with other UltraTerm Computer Use bundles.
- The CLI and the app agent exchange one JSON message per line over that socket through `LineDelimitedSocketChannel`, which reads in 64 KiB chunks, delivers a trailing partial line at EOF, and treats a single line larger than 64 MiB as a framing error that drops the connection. `doctor --status-only` and `tools` never use the agent. `preview` and `record` also run in the CLI process instead of the agent, so that SIGINT and SIGTERM cancel a running capture cleanly and no viewer UI opens.
- Before sending `call`, the macOS CLI resolves `--args-file` / `--calls-file` against the caller's working directory. It does not change the agent's working directory. Relative paths, absolute paths and paths with spaces all work. Missing-file errors include the resolved path.
- The CLI and the MCP proxy forward environment variables with the `ULTRATERM_COMPUTER_USE_` prefix from the calling process to the app agent with each request. They override the agent environment only while that request runs. This keeps the process-level safety gate for `click_method=global` and the debug switches under the caller's configuration in the app-agent architecture.
- The main window renders two permission cards, `Accessibility` and `Screen & System Audio Recording`, with `Allow` / `Done` states. It converges the state after relaunch. When both permissions are granted, it closes automatically; the user does not need to quit it manually.
- The auxiliary drag panel jumps to the matching `System Settings` page. After `Allow` is clicked, the panel enters with a spring and curved-frame animation that starts at the button's position in the main window, then settles at the lower edge of the `System Settings` content area. Without Accessibility permission, or when the target control cannot be read, the panel stays centered below the right-hand content area of the window, close to the window's bottom edge. When permission is available, it prefers to attach below the `+ / -` control container of the first permission list and adapts to the list width. AX reads run with bounded execution inside a background actor. They traverse only the container and do not enter app rows. The audio list below in Screen & System Audio Recording never becomes a substitute anchor. If the upper control is not visible, the panel falls back to the window's bottom edge. In window ordering, the panel is explicitly placed above the current `System Settings` window so that the permission list content does not cover it. This also minimizes interference with the scroll area of System Settings itself. The panel has an explicit back button, which lets the user interrupt the current guidance and return to the onboarding main window to choose a permission step again. If the entry animation is interrupted because System Settings lost focus, showing the panel again restores its full size and opacity. Intermediate animation frames do not take part in calculating the next target size.
- Permission state merges the persistent TCC grant records with the runtime preflight of the current app process. If any matching TCC client is granted, the state is treated as granted. This avoids the CLI subprocess and the GUI app disagreeing about permission state. If the current `.app` process already passes `AXIsProcessTrusted()` / `CGPreflightScreenCaptureAccess()`, the state is treated as granted immediately. A stale or mismatched TCC path record therefore does not keep the onboarding overlay on screen. The official release `UltraTerm Computer Use.app` remains the reference build. Local debug and dev packages are named explicitly `UltraTerm Computer Use (Dev).app`. When a dev bundle runs, it prefers the current dev copy, so System Settings does not show two identically named entries.

### 2. MCP Layer

- The external transport for MCP hosts is still `stdio`. On macOS, an additional local Unix domain socket proxy sits between the terminal CLI and the `.app` app agent. It ensures that real automation runs under the app bundle's permission identity.
- When `ULTRATERM_COMPUTER_USE_VISUAL_CURSOR` is not explicitly disabled, the `mcp` command switches to a minimal AppKit runtime. The main thread keeps an event loop to host the overlay UI. The stdio server keeps reading and responding serially on a background thread.
- Request framing uses one JSON-RPC message per line.
- Supported methods:
  - `initialize`
  - `notifications/initialized`
  - `notifications/turn-ended`
  - `ping`
  - `tools/list`
  - `tools/call`
- The macOS stdio MCP server, the app agent and the proxy release an autorelease pool per request. Tool dispatch has its own pool. The app agent checks for disconnects only while it handles a request and writes a response. When idle, disconnects are detected by a blocking read. Regression entry point: `scripts/tests/macos-request-lifecycle-smoke.mjs`.
- `notifications/turn-ended` is the explicit turn boundary hook in the open-source version. On receipt, it cleans up the visual cursor overlay, the occlusion keep-alive and the agent display in the current process. The CLI command `ultraterm-computer-use turn-ended [payload]` also sends a macOS distributed notification to the running AppKit MCP / app-agent processes, which perform the same kind of cleanup. It can be wired to the after-agent payload of Codex legacy notify. Stdio server exit and app-agent client connection close also run this session cleanup.

### 3. Tool Service Layer

- `ComputerUseService` maps Computer Use tool requests to local capabilities. `ComputerUseToolDispatcher` consolidates the argument parsing and service method dispatch of native tools into one layer shared by the MCP server and `ultraterm-computer-use call`.
- The Codex plugin does not register an MCP server by default: it ships the `ultraterm-computer-use` skill, which drives the CLI. `plugins/ultraterm-computer-use/optional/mcp.json` is the opt-in entry. It starts `scripts/node-repl/ultraterm-computer-use-repl.mjs`, whose adapter connects to the same native runtime as a child MCP client and lists only `js` / `js_reset` to the outside. JavaScript calls native tools through asynchronous app-bound APIs such as `cua.getApp(...)`, `app.click(...)` and `app.getAXState()`.
- The macOS app agent runs every one-shot `call` request against one `ComputerUseService` (`UltraTermComputerUseSharedCallService`: serialized, dropped after 10 minutes idle). That is what lets `state_id` and element indexes cross separate CLI processes; the MCP connections keep their own per-connection service. `call` output is rendered once in `CallCommand.swift` and used by both the CLI process and the agent, so both print the same bytes.
- The REPL uses the evaluator built into Node.js, so top-level `await` and lexical bindings persist across calls. The kernel that runs the code lives in a Worker. On timeout, the Worker is terminated and a clean session is rebuilt, so that `while (true)` cannot hang the MCP transport.
- The npm launcher also provides `ultraterm-computer-use js` and `ultraterm-computer-use repl`. `js` runs a one-off Worker and native MCP session. `repl` keeps the same session and bindings in the current terminal. When either exits, the Worker and the native MCP child are closed. `ultraterm-computer-use capabilities [--json]` reports, without starting the native MCP server, whether Node, the adapter, the kernel and the native artifact for the current platform are all present. Help always shows the code-first commands and marks their availability. It does not hide interfaces dynamically based on the environment.
- The npm bin currently starts through `#!/usr/bin/env node`. A shell without Node therefore cannot reach the help or capability check. After startup, the launcher reuses `process.execPath` and does not resolve Node from PATH again. If zero-Node prerequisites are required in the future, the outermost entry point should be replaced with a native bootstrap, or Node should be shipped with the package.
- `ultraterm-computer-use mcp` remains available as an optional compatibility command with the same tools as `call`, so MCP-only hosts and smoke tests do not need to switch.
- `list_apps` fetches app bundles from the standard application directories through a Spotlight metadata query. It reads system metadata such as `kMDItemUseCount` and `kMDItemLastUsedDate_Ranking`, then merges them with the running apps from `NSWorkspace`. The output is a view of apps that are "currently running or used in the last 14 days".
- `get_app_state` prefers real AX data and window screenshots. A real app must have either a non-minimized `AXWindow` or a focused `AXSheet`, and a matching on-screen `CGWindow`. If the target app is only hidden or temporarily has no on-screen window, the tool changes nothing and fails with a named error that starts `The app has no window that can be read in the background`.

  Only when `ULTRATERM_COMPUTER_USE_ALLOW_FOREGROUND=1` is set does it make a best-effort attempt to unhide, activate, run `open -b`, unminimize and `AXRaise`, then retry briefly. If the window still cannot be matched after that recovery, it returns the reference-style error `Apple event error -10005: cgWindowNotFound`. It does not present an application root node or a window without a screenshot as an operable state.

  When the target is the fixture app in this repository, the tool falls back to the synthetic state exported by the fixture. The real AX tree renders up to 1200 nodes and 64 levels of depth by default on macOS, Linux and Windows. Explicit `get_app_state` and `snapshot` calls can override the budget with `max_tree_nodes` / `max_tree_depth`.

  Refresh results from action tools still use the default budget. Snapshot text is truncated to 500 characters by default. Explicit `get_app_state` and `snapshot` calls can override this with a positive integer `text_limit` or `"max"`.

  Refresh results from action tools still use the 500-character default. For deep UI such as Electron or WebView, the renderer collapses empty `AXGroup` / `AXUnknown` wrappers, filters `AXScrollToVisible` noise and empty string attributes. This prevents action-critical input fields from being pushed out of the node budget by semantically empty containers.

  However, `AXPress` / `AXConfirm` / `AXOpen` children of generic nodes form text summary boundaries, so several clickable options are not merged into one container. If such an action node has a valid frame, a compact size, and no descendant `AXLink` with a URL, it is kept as a `button` with a window-relative `Frame`. A short text descendant serves as the button summary, so both icon-only and text-based web controls get distinct `element_index` values.

  If a descendant `AXLink` with a URL exists, the generic wrapper and link children are kept, so that a navigation link is not swallowed by a summary. For native open panels and Finder column views, which place their content in `AXContents` / `AXVisibleChildren`, visible file items are also included in the element tree.
- On all three platforms, snapshots first select visible action controls, ordinary interface regions, and then collections and clearly off-screen content, all within a bounded set of candidates. Ancestors are kept, and output follows the original tree order, so indexes map to the actual elements. The default of 1200 nodes is unchanged. The candidate scan is limited to `max(64, min(max_tree_nodes, 2500) × 4)`. When nodes, candidates or depth are insufficient, the output explicitly says the tree was truncated. On macOS, collections prefer `AXVisibleChildren` and no longer merge the full list. On Linux, both SHOWING and scroll-area geometry are checked, so off-screen GTK table cells that still declare SHOWING are excluded. Elements with unknown visibility are not discarded directly. See [Tree budget](tree-budget.md).
- The macOS AX renderer, on the first visit to an element during one tree walk, reads common non-sensitive attributes in a batch with one `AXUIElementCopyMultipleAttributeValues` call. After confirming that the control is not a password field, it reads AXValue. Attributes, action names and settable state are cached only within that walk. Unsupported and no-value results are cached. Transient errors are not cached and can be re-read individually. Re-reads and lazy-web rewalks build a new cache. Action reads, focus and window queries do not enter this cache. Setting `ULTRATERM_COMPUTER_USE_DISABLE_AX_READ_CACHE=1` turns the cache off for output comparison diagnostics. Semantic AX fixture tests drive the real renderer with an injected attribute source. They verify that the role, name, value, the element behind each action number, and the recorded frame stay consistent. Real AppKit comparison entry point: `node scripts/tests/macos-ax-batch-smoke.mjs <signed-ultraterm-computer-use-executable> [baseline-executable]`. It compares the full text, measures the actual read time, and verifies the new state after a click. Replace `<signed-ultraterm-computer-use-executable>` with the signed `ultraterm-computer-use` executable.
- On macOS, a focused sheet uses its own window ID. The AX tree, screenshots and input coordinates all follow the panel. `query` can look up the focused sheet by this ID. When a control's `AXWindow` points to the parent document, ownership is confirmed by walking a bounded parent chain. After the read budget ends, the default AX timeout is restored, so that closing a panel successfully does not cause a false action failure. After the popup closes, an old query index is rejected. When a sheet is explicitly docked, its parent window is moved. If the parent window cannot be confirmed, an error is returned. Real panel regression: `node scripts/tests/macos-sheet-smoke.mjs <signed-ultraterm-computer-use-executable>`. It uses temporary files and normal authorization, and does not enable the global pointer fallback.
- The descriptions and input schemas of the 9 core MCP tools follow the official `computer-use` wording and parameter surface. On macOS, an extra `query` tool is provided. The goal is to minimize prompt and tool-surface differences on the host side.
- The JS REPL API is aligned with the current official code-first form, which uses asynchronous app bindings. It is not a simple wrapper that turns discrete tools into synchronous functions. The `windowPlacement` option of snapshot and the `keyMethod` option of keyboard actions are converted into snake_case native tool parameters. The implementation does not copy or run any proprietary package. Protocol and behaviour are documented in the JS REPL reference in this repository.
- `ultraterm-computer-use call <tool> --args '{...}'` prints the MCP-style JSON result directly. `ultraterm-computer-use call --calls '[...]'` / `--calls-file <path>` runs the tool calls in a JSON array sequentially within one process. It reuses the same in-memory state of `ComputerUseService`, so an action tool that follows `get_app_state` can keep using the `element_index` values of the same snapshot.

  Sequential execution sleeps 0.2 seconds between successful adjacent actions by default. You can override this with `--sleep <seconds>`. Execution stops after a tool result with `isError=true`.
- On the macOS app-agent path for real apps, `get_app_state` and the action tools keep only one layer of blocking: a denylist of password manager bundles. A bundle identifier passed directly returns a safety denial. Name matches do not resolve to those apps by default. Terminals, browsers and system components are no longer built-in blocked targets.
- For ordinary apps, element frames are output as window-relative coordinates with the origin at the window's top-left corner. This makes it easier to align `element_index` and screenshot coordinates in one reference frame later. Click AX hit-testing receives window points and adds only the window's screen origin. Screenshot coordinates are converted once at the entry point. Element-index clicks do not depend on screenshots. Real AppKit regression: `node scripts/tests/macos-hit-test-smoke.mjs <signed-ultraterm-computer-use-executable>`. It needs existing Accessibility and Screen Recording permissions and a Retina display.
- On all three platforms, explicit `get_app_state` supports `include_ax` / `include_screenshot`. Both default to true, and at least one must remain enabled. The JS equivalents are `includeAX` / `includeScreenshot`. The CLI snapshot command offers the same parameters in hyphenated form. Turning AX off skips the tree, focus and selection, and invalidates old snapshot and query indexes and aliases. Turning the screenshot off skips capture and encoding. Element operations still work, but coordinate operations based on the screenshot require fetching the image again. Parameters are forwarded through the macOS app agent. They do not change action read-back and do not perform automatic image de-duplication. See [Selective observation](selective-observation.md).
- On all three platforms, `set_value` verifies the actual value of an ordinary control before returning success. On macOS, password fields are marked to confirm only that the write was accepted; the password is not read back. Text preserves whitespace and Unicode exactly, and an empty string can clear the value. Only native numeric and boolean attributes are compared by their matching types. Turning off full action read-back does not skip verification. It polls for at most 0.6 seconds and does not rewrite the value. After a failure, observe again before deciding whether to retry. See [Set value verification](set-value-verification.md).
- On macOS, `query` and `select_text` are provided in addition to the core tools, so the native surface has 11 tools. Linux and Windows keep the 9 core tools. The JS call `app.selectText(elementIndex, text, {prefix?, suffix?, selection?})` reuses snapshot or query indexes. It supports selecting text along with the characters before and after the cursor. It locates text by literal string and UTF-16 offsets, and rejects ambiguous matches. Before writing and before returning, it checks the session. It verifies that the text is unchanged and that the actual selection equals the requested one. Verification cannot be skipped even when full read-back is turned off. Failures are reported through a native `isError` or a JS exception. Result refresh uses read-only recovery and does not recover by activating the app, sending keyboard input or using a real pointer.
- `click` and `set_value` drive a transparent `SoftwareCursorOverlay` window before and after the real action. The movement phases of both now share one heading-driven, official-style motion core. It feeds both the current cursor heading and the final resting pose into the path selector. It prefers C-shaped or single-sided large-arc paths that turn first when needed and then advance along the nose direction. On first display, the start point is generated from the AppKit global `(0,0)` window origin, following the fresh state of the reference binary. Later actions reuse the previous visible tip. The cursor that is actually shown is no longer equal to the path samples. It passes through a separate visual dynamics state, which continuously advances the visible tip, velocity, angle and fog/offset. `click` ends with a click pulse and a more visible but still small rotate wobble. `set_value` only settles and idles, with no pulse. After either finishes, the cursor stays idle at the target point. When the next action begins, the tip stays anchored and keeps only a perceptible small angular wobble. Cleanup happens only after 30 seconds without a new action, so consecutive tool calls do not restart from a fresh `(0,0)` each time. If the host sends `turn-ended` when a task or turn ends, the cursor disappears immediately and the position state for the turn is cleared.
- The overlay follows the target window's movement through an anchor relative to the target point. Movement, settling, click feedback and idle all read the latest cached frame. When a position change is detected, the visible tip is repositioned directly and the old velocity is cleared. Window frames are read serially in the background, at most 30 Hz and with at most one request in flight, so that AX calls cannot block the render thread. It prefers the AX window held by the snapshot. It uses the window list only when no AX element is available. If a read fails, the last valid frame is kept. Tracking state is kept only for the current window and is released after a reset or idle timeout. This layer adjusts only the displayed position. Input delivery still uses the existing path.
- The visual style of the overlay no longer crops a small `SoftwareCursor` image from the official app bundle. The main MCP runtime now prefers rendering the stored official runtime baseline PNG image in the repository. Only when that resource is missing does it fall back to the programmatic pointer and fog fallback inside `UltraTermComputerUseKit`. The hit-point anchor stays at the same tip-offset positions on the `126x126` canvas. The neutral heading of the glyph keeps the `-3π/4` value of the official baseline. The main runtime overlay window moves in AppKit global coordinates. Therefore, before the y-down screen-space click targets produced by AX / `CGWindowList` are passed to the overlay, they are converted to the corresponding screen's AppKit global coordinates. Path selection uses the AppKit forward heading that is actually visible on screen. Before entering the visual dynamics or render state, the y axis of velocity is flipped back to the y-down screen state. The AppKit drawing layer then flips the angle and `dy`. The programmatic fallback keeps a neutral artwork correction. It aligns the artwork's natural outline axis with the `-3π/4` forward direction of the official baseline.
- The overlay level is no longer fixed at `.floating`. It follows the window ID and layer of the target window that the snapshot hit, and places itself above that target window instead of above every foreground app.
- The overlay's curved path is no longer produced only from a fixed Bezier template. The current mainline uses a family of heading-driven candidates constrained by reverse-engineering analysis. Candidates keep only the families `direct`, `turn`, `brake` and `orbit`, which reliably produce a single main arc. Target-window hit policy remains the tie-breaker between candidates of the same kind. The 20 paths and scores recovered from the reference binary are not used as the default runtime chooser.
- The overlay's progress curve is no longer a fixed `easeInOut`. The mainline now reuses the spring / `VelocityVerlet` shape of the official `response=1.4`, `dampingFraction=0.9`, `dt=1/240` settings. The spring shape is kept, but it is stretched or squeezed to a fixed move duration.

  The default is 0.18 seconds. The earlier default, the recovered endpoint-lock time `343 / 240 = 1.4291667s`, held every click for about 1.43 seconds. `ULTRATERM_COMPUTER_USE_VISUAL_CURSOR_MOVE_DURATION` sets the duration in seconds, limited to 0 to 2.

  `0` jumps to the target. The idle sway runs at 20 Hz instead of 60 Hz.
- The overlay no longer relies on a temporary `terminal settle` patch to finish the motion. The mainline now uses one two-layer model for all phases: the path layer provides the target point, and the visual dynamics layer provides the visible pose. The end of a move, the pulse and idle therefore share the same state. The endpoint can no longer lock with only an angle change left in place.
- The overlay's render input has been extended from a single `rotation` to `rotation + cursorBodyOffset + fogOffset + fogScale`. This makes the speed lag visible in the image, not only in internal loop state. `rotation` now follows the reference binary's split between `SoftwareCursorStyle.angle` and `CursorView._animatedAngleOffsetDegrees`. The main heading that follows the motion direction is no longer compressed into the same small restricted angle as a small wiggle offset.
- For ordinary apps, action tools use a policy of "non-intrusive first, with physical pointer paths as explicit opt-in":
  - `perform_secondary_action` only performs AX actions that the target element already exposes. AppKit custom action descriptors in browsers (for example `Name:close tab ...`) are shown as short names and mapped exactly back to the filtered original AX action, which avoids a mismatch between raw and rendered actions. If a short name conflicts with another display name or with any other original AX action (including filtered ones, case-insensitive), the full descriptor is kept, so the output selector is not captured by an exact match on a raw action. Invalid or ambiguous actions return the reference-style error `... is not a valid secondary action for ...`. The fixture's `Raise` path no longer prepares global physical pointer input for testing.
  - `set_value` first uses `AXUIElementIsAttributeSettable(kAXValueAttribute)` to check that the target is really a settable value element. It calls `AXUIElementSetAttributeValue` only when the element is settable. When it is not settable, it returns the reference-style non-settable error. It does not fall back to keyboard input, the clipboard, or an undocumented text replacement interface.
  - `click.click_method` is an optional extension of the open-source version. It supports `auto` (default), `accessibility`, `app_post`, `sky_click` and `global`. Without the parameter, the original automatic routing is used. Explicit modes never fall back silently to another implementation. `accessibility` accepts only `element_index`. Other mouse paths can use the computed point of `element_index` or the raw `x/y` coordinates.
  - For element-targeted left clicks in `auto` mode, the tool first tries the `AXSelectedChildren` selection of native lists, then semantic activation actions such as `AXPress`, `AXConfirm` and `AXOpen`. If the target itself is not clickable, it continues with the target's descendant AX elements (for example a cell that exposes `AXOpen` under a Finder sidebar row) and with the AX hit-test result near the hit point. Finally it enters the existing non-AX branch. When the global pointer environment variable is not enabled, this uses `postToPid` targeted mouse events. When enabled, it uses global HID events directly. Activation-only fallbacks such as `AXRaise`, `kAXMainAttribute` and `kAXFocusedAttribute` are allowed only for window-level elements. This prevents static text or containers from reporting "focus obtained" as "click handled". `click_count > 1` also prefers repeating available AX actions.
  - Explicit `click_method=accessibility` performs only the AX semantic actions described above. Explicit `click_method=app_post` bypasses AX candidates and descendant scans. It sends `mouseMoved`, down and up events directly to the target process through `CGEvent.postToPid`. Explicit `click_method=sky_click` accepts only left single and double clicks on macOS. It verifies that the `CGWindowID` of the current snapshot is still owned by the same PID and is on screen. It uses `SLPSPostEventRecordTo` only to put the target app briefly into a synthetic-active state. It never sends a defocus record to the real foreground app. It then sends the target move, a `(-1,-1)` primer and the real down/up events, following a Chromium-compatible recipe. Each mouse event is delivered through both the dynamically resolved `SLEventPostToPid` and the public `postToPid`, with window-local location, PID/window and click-group fields. After the renderer settles, only the target's synthetic-active state is revoked. Action-result snapshot refresh for `sky_click` also forbids activate or `AXRaise` recovery. If the target state is momentarily unreadable, the action fails immediately. It does not change `auto`, and no step falls back when it fails. Explicit `click_method=global` also bypasses AX, but sends system-level pointer events through `.cghidEventTap`. `global` also requires `ULTRATERM_COMPUTER_USE_ALLOW_GLOBAL_POINTER_FALLBACKS=1`. Without it, the request is rejected before moving the visual cursor or sending input.
  - `get_app_state` looks for the target window among on-screen windows first, then among all windows. Windows on other Spaces therefore do not trigger activate or raise recovery. After it captures an unoccluded window, it turns off that window's WindowServer occlusion notifications (`WindowOcclusionKeepAlive`). Later, when the window is occluded or its Space changes, Chromium, Electron and WebKit still keep the page and `AXWebArea`. The keep-alive stores the raw on/off state returned by the SPI. It restores that state on turn-ended, on MCP or app-agent connection close, on normal server shutdown, or on process exit. A record whose restore failed is kept for later retry. Because snapshots maintain this state, macOS `get_app_state` does not declare `readOnlyHint`. The web AX tree of Chromium-based apps is lazily loaded. While the window is visible, it is walked again for up to 3 seconds. While occluded, a note is appended to the end of the tree. `sky_click` no longer requires the window to be on screen.  - The main window capture path is the WindowServer `SLSHWCaptureWindowList` (works on any Space and when occluded, 15–45 ms). It is used only when the window lies entirely within a single display and the pixel ratio is correct. For off-screen windows, cross-display windows or abnormal hardware capture, the tool falls back to whole-window ScreenCaptureKit capture. If the ratio does not match, no image is returned. AX geometry is filtered for non-finite values during snapshot, query and click re-reads. Render coordinates have a separate integer conversion guard. For reproduction and limits, see [macOS snapshot geometry](macos-snapshot-geometry.md). The AX root window binds directly to its `CGWindowID` through `_AXUIElementGetWindow`. The fixed intervals of the input recipes are calibration knobs that can be tuned with environment variables. Their defaults come from benchmarks.
  - `get_app_state.window_placement` is controlled by `virtualDisplay.enabled` (default `false`; the ENV `ULTRATERM_COMPUTER_USE_VIRTUAL_DISPLAY_ENABLED` takes precedence). When it is off, the option does not appear in the tool schema or JS hints. `agent_display` is rejected before window lookup and before any underlying creation. `restore` and session cleanup keep their restore capability. When enabled, it is an optional extension of the open-source version with the values `keep` (default), `agent_display` and `restore`. `agent_display` creates an agent-dedicated virtual display through `AgentDisplay` and `packages/UltraTermComputerUseVirtualDisplayShim`. It uses the AX position to move the target window's frame onto that display, without activating or raising it. Windows that are occluded or on another Space become truly visible to their app. `restore` restores all windows that the current runtime has parked, by app PID. Session cleanup or process exit also restores all windows and destroys the display. When restoration fails, the original position record and the virtual display are kept. This avoids recording an unrestored window as successful and allows a later retry. Windows that were closed have their records cleared directly. The shim catches the Objective-C exceptions raised by private KVC/selector calls and turns incompatible systems into a creation failure. On Windows and Linux, values other than `keep` return unsupported.
  - `type_text.key_method` and `press_key.key_method` are optional extensions of the open-source version. They support `auto` (default) and the macOS-only `sky_key`. `sky_key` reuses the target-only synthetic-active record from `sky_click`. It then sends yabai's make-key-window record, so that the target app makes the current snapshot window its key window within the process. After that, keyboard delivery uses the existing `CGEvent.postToPid` path. Single-character shortcuts with `cmd` instead find the matching menu item in the target's AX menu bar and perform `AXPress`. It does not require the window to be on screen, so it works for other Spaces. It fails closed for hidden apps. Like `sky_click`, the action-result snapshot uses the read-only recovery policy.
  - For a `text` row synthesized by the renderer as a summary, `click` no longer clicks the center of the parent container by default. Such elements use a safe anchor on the left side. For descendant candidates of ordinary row, container and text elements, compact hover actions on the right side (for example a "Done" check mark in an Electron chat app's session list) are filtered out. This prevents a main-row click from accidentally triggering a side action. For WebArea-synthesized text in Electron-based apps, the tool first looks for the nearest row-level `AXPress` ancestor and performs it silently. This avoids using a physical mouse to click the row. WebAreas in browsers do not use this Electron-scoped row-ancestor optimization. They keep the generic link and container click path. If a hit point resolves only to an Electron or WebArea-level AX element covering the whole page, the tool no longer scans every descendant candidate of the large container. This prevents a single row click from being taken over by a clickable element far away.
  - `AXUIElementCopyElementAtPosition` performs coordinate hit-testing, so that a coordinate click can, where possible, be resolved back to an operable AX element. Descendant scanning for click candidates only considers elements that fall on the click target. A coordinate click requires a descendant frame that contains the click point. An element-targeted click requires a descendant frame that overlaps the target's click frame. When the click lands on blank space, the best candidate is often the window itself. In that case the tool does not press the smallest button elsewhere in the window (for example a close button). Instead it falls through to `postToPid` targeted mouse events. Descendant frames must be valid and have non-zero area. An explicit click on the window or sheet root index skips the descendant and nearby hit-test searches, and goes directly to the existing window Raise / focus fallback. An explicit click on a close button can still execute. To verify the real window behaviour, run `node scripts/tests/macos-hit-test-smoke.mjs <signed-ultraterm-computer-use-executable> --descendant-guards`. When someone is using the desktop, you can add `--allow-desktop-activity` to explicitly skip the foreground and pointer stability assertions.
  - `CGEvent.postToPid` sends keyboard events to a target directly, so that `type_text` and `press_key` do not need to take the foreground. `type_text` groups text into extended grapheme clusters and sends them as small batches of `keyboardSetUnicodeString` events. This prevents Chinese punctuation, emoji, surrogate pairs and combining characters from being split into individual UTF-16 code units, which would scramble or distort them in Electron rich-text fields. On macOS, `type_text(auto)` reads the current focus on each call. If the read fails, it does not use a cached target. It checks focus and the session again before writing. It prefers writing `AXSelectedText`, when that is writable without needing `AXValue`. If that is not supported, it replaces the matching range through `AXValue` and restores the cursor, but only when the full text and the UTF-16 selection are readable, and the value and selection are both writable and unchanged. Known placeholder handling is preserved. If an AX write has already been attempted and failed, the tool reports an error and does not append or resend. Other editable targets still use the process-targeted keyboard fallback, and whether the app accepts it depends on the app. Real regression: `node scripts/tests/macos-text-input-smoke.mjs <signed-ultraterm-computer-use-executable>`. If the currently focused element is not an editable text target, `type_text` returns an error asking you to click the text input area first or to use `set_value`. It no longer reports success for background keyboard delivery that has no effect. The xdotool parser for `press_key` covers common key names from the reference binary's key table, including `BackSpace`, `Page_Up`, `Prior` / `Next`, `F1...F12` and `KP_*` aliases.
  - `scroll.pages` matches the `number` schema of the official `1.0.755`, so fractional page counts are supported. For an integer page count where the target exposes `AXScroll*ByPage`, the AX action is preferred. Otherwise the tool sends scroll events directly to the target process through `CGEvent.postToPid`.
  - `drag` is still a coordinate-only API. By default it no longer uses the global `.cghidEventTap` mouse events. Instead it sends mouse move, down, dragged and up events to the target with `CGEvent.postToPid`, so the user's real hardware cursor is not moved. The `x/y` values of these coordinate tools are first interpreted as screenshot pixel coordinates. They are then mapped back to window point or Quartz global coordinates using the ratio between the screenshot pixel size and the target window bounds. This prevents 2x pixels on a Retina window from being misread as 1x points, which would make clicks land in the wrong place.
  - `click`, `scroll` and `drag` do not use the global `.cghidEventTap` in the default configuration where the environment variable is not enabled. They therefore do not move or take over the user's real mouse. `ULTRATERM_COMPUTER_USE_ALLOW_GLOBAL_POINTER_FALLBACKS=1` is the process-level safety gate for global pointer capabilities.

    Explicit `click_method=global` must still pass this authorization. The default path never calls `NSRunningApplication.activate`. With the switch on, the global path first raises the window through accessibility, or else activates the app.

    The result of `drag` adds a `Drag delivered via ...` text item after the snapshot text and before the screenshot. It states whether the delivery used targeted `app_post` or the global pointer path. In the default path it also notes that `postToPid` events do not pass through the window server.

    So they cannot drive window server drag sessions such as moving a window, selecting text by dragging, or dragging files in Finder. The tool description of `drag` also documents this limit and the related environment variable. When the global path is explicitly enabled, drag uses the default event source and posts to the HID tap.

    It interpolates by distance and writes a displacement delta for each step. On macOS 26 and later, the down, dragged and up events share a gesture event number, so that the window server can recognize a real drag session for moving windows, selecting text and dragging in Finder.

- For the fixture's `get_app_state` and a small number of test-only actions, `FixtureBridge` uses an explicit command channel.
- This bridge serves only the deterministic smoke path inside the repository. It is not a capability boundary for real third-party apps.

### 5. Windows Runtime

- The Windows runtime lives in `apps/UltraTermComputerUseWindows`. It is maintained in Go and contains the CLI, the `call --calls` sequence, MCP JSON-RPC, the tool schema, and an in-process snapshot cache.
- The build entry point is `scripts/build-ultraterm-computer-use-windows.sh --arch arm64|amd64`. By default it writes to `dist/windows/<arch>/ultraterm-computer-use.exe`. The npm release package bundles both Windows artifacts into the existing root and alias packages. The Node launcher selects one automatically based on `process.platform/process.arch`.
- The Go runtime embeds `runtime.ps1` through `go:embed`. When a tool call runs, it writes the script to disk temporarily and invokes Windows PowerShell. The PowerShell bridge uses `System.Windows.Automation` for app, window and element discovery, tree rendering, UIA pattern actions, ValuePattern set value and ScrollPattern scrolling. When the target app does not expose the matching pattern, it falls back to Win32 window messages sent with `PostMessage` / `SendMessage`. When the PowerShell process starts, it aligns itself to physical coordinate space with `SetProcessDpiAwarenessContext` / `SetThreadDpiAwarenessContext`. This is needed because `windowBounds` in the operation files and UIA frames are physical pixels, while a DPI-unaware process gets virtualized values from `GetSystemMetrics` and `GetWindowRect`.
- By default, the Windows runtime connects only to apps that are already running. When `get_app_state` cannot find the process, it does not call `Start-Process` automatically. It also does not allow the `SetFocus` secondary action by default. These two paths that take the foreground must be enabled explicitly with `ULTRATERM_COMPUTER_USE_WINDOWS_ALLOW_APP_LAUNCH=1` and `ULTRATERM_COMPUTER_USE_WINDOWS_ALLOW_FOCUS_ACTIONS=1`. By default, `type_text` prefers to send `EM_REPLACESEL` to the Edit or RichEdit child HWND that has keyboard focus. This preserves the current selection. When focus is unknown, it selects the only writable text control in the window. That count includes controls without ValuePattern and read-only controls. If there are several, it refuses. It no longer uses the UIA `ValuePattern.SetValue` fallback by default, because that can trigger foreground activation. To get the old behaviour, set `ULTRATERM_COMPUTER_USE_WINDOWS_ALLOW_UIA_TEXT_FALLBACK=1`. UIA patterns and the Win32 message fallback are still best-effort. Many controls respond in the background. However, Windows has no background keyboard and mouse input model that is equivalent to macOS AX for every GUI toolkit.
- Windows screenshots first check that the main window is visible, not minimized, not DWM-cloaked, intersects the virtual screen, and is at least 64 pixels wide and high with an area of at least 20,000 pixels. `list_apps` also lists only windows that pass these capturability checks. After the PowerShell bridge passes, the Go layer decodes the PNG header and rechecks it against the same size threshold. If any check fails, the snapshot can still return the UI Automation tree, but it omits the MCP `image` block. Coordinate click and drag fail explicitly. Element-targeted actions can still be tried. The implementation does not enlarge, pad or generate placeholder screenshots for degenerate windows. The intersection test between the window and the virtual screen runs in physical coordinates. A window that is entirely outside the virtualized screen at 125% or 150% scaling is therefore not wrongly judged as non-capturable.
- The protocol surface of these 9 tools matches the macOS main line: `list_apps`, `get_app_state`, `click`, `perform_secondary_action`, `scroll`, `drag`, `type_text`, `press_key`, `set_value`. Element-targeted actions preferentially reuse the runtime ID and automation metadata from the previous `get_app_state`. Coordinate actions use screenshot-relative or window-relative coordinates.
- Windows screenshots capture the target HWND through `PrintWindow(PW_RENDERFULLCONTENT)`. If this fails, the image is omitted. The tool does not fall back to desktop pixels, which might include other apps. The window geometry is checked before and after capture. Posted clicks locate the recipient within the target child-window hierarchy. They verify the window, element and child-control local coordinates, check the result of message delivery, and try to release the mouse if an exception occurs. For a real occlusion screenshot and nested control regression, see [Windows targeting](windows-targeting.md). GPU and protected windows still depend on whether the app supports `PrintWindow`.
- After a Windows action is delivered, the tool reports the action as delivered even if reading the window fails afterwards (for example, when the click closed the window). The result states why the read failed. It discards the app's old snapshot and requires `get_app_state` as the next step, so that a model retry does not cause a duplicate action. When an action tool times out after 30 seconds or the bridge communication fails, it reports that the outcome is unknown and may have been delivered. These failures also invalidate all snapshot aliases in the same process, so old indexes cannot be reused.
- Windows element actions verify SHA-256 digests of the original RuntimeId, control type, AutomationId and full name. If the reference is invalid or its identity has changed, the tool requires re-observation and does not search for a same-named substitute. The name digest is independent of the display `text_limit`, so changes after truncation are still detected.
- Windows resolves apps by window rather than `Process.MainWindowHandle`. `EnumWindows` lists visible, unowned top-level windows in z-order. Matching is done in turn by PID, process name and window title (exact match first, then contains). A UWP `ApplicationFrameWindow` is attributed to the process of the CoreWindow it hosts. As a result, UWP apps such as `CalculatorApp` can be found by their own process names, and several UWP apps no longer share one title from ApplicationFrameHost. `list_apps` uses the same list. When a main window is disabled by a modal dialog, the tool follows the owner chain to find the innermost dialog and uses it as the root. A numeric PID never falls back to title matching. Title containment is matched literally. Posted input fallback is refused for windows whose host HWND belongs to a different process than the content, so input is not delivered to the host. See [Window targeting](windows-targeting.md).
- When the target process integrity level is higher than the Windows runtime (the target runs as administrator and UltraTerm Computer Use does not), all actions are rejected before sending. For hosted windows, both the content and host processes are checked. UIPI may block this kind of input, and the SendInput return value alone cannot tell why it was blocked. If the integrity level cannot be read, input is also rejected. `get_app_state` still works.
- For Windows Toggle, Select, Expand and Collapse (including `click` through SelectionItem and Toggle patterns), the tool sends the action once and then reads the state back for at most 0.6 seconds. If the expected state is not reached, it reports an error and asks for re-observation. When a ScrollPattern call throws, it reports an uncertain outcome. It no longer hands off to a wheel fallback that might scroll twice. See [Set value verification](set-value-verification.md).
- Before reading UI Automation or sending an action, the tool probes whether the target window is still processing messages (`IsHungAppWindow`, plus a 1-second `SendMessageTimeout(WM_NULL, SMTO_ABORTIFHUNG)`). If the window fails to respond twice in a row, it reports that the app is not responding. Probe errors such as permission denial are reported separately. Calls no longer hang until the 30-second timeout, and input is no longer queued to a hung window's message queue.
- `click_method=accessibility` on Windows uses UIA, and `app_post` always uses HWND messages. `click_method=global` requires `ULTRATERM_COMPUTER_USE_ALLOW_GLOBAL_POINTER_FALLBACKS=1`. When it is enabled, auto clicks, the scroll fallback used when ScrollPattern is missing, and drag can also use the real pointer. `press_key` in auto mode always uses window messages. It sends keys to the control that has keyboard focus inside the window. It rejects key combinations whose modifiers window messages cannot carry. A real key press requires explicit `key_method=global` and the same environment switch. Physical input checks the SendInput return value and releases keys and mouse buttons in a `finally` block. It verifies the observed PID and HWND, the latest geometry, the foreground window, and the window that the coordinate hits. If a normal SetForegroundWindow fails, the action is refused. The tool does not simulate Alt to force the foreground. The macOS-only `sky_click` and `sky_key` remain explicitly rejected. See [Windows input notes](windows-input.md).
- Windows UI Automation must run inside the desktop session of the logged-in user. When run over SSH as a background process detached from the desktop, PowerShell can start and return JSON. However, the system may not expose top-level windows to it. In that case `list_apps` returns an empty list, and `get_app_state` may return `appNotFound(...)`.
- Windows has a separate WPF observation fixture and a Windows smoke test. They cover observation, scrolling, physical input and screenshot boundaries. Coverage of the other tools and toolkits is still missing. The visual cursor overlay, onboarding and code signing are also still pending. Windows has an install script at `scripts/install.ps1`.

### 6. Linux Runtime

- The Linux runtime lives in `apps/UltraTermComputerUseLinux`. It is maintained in Go and contains the CLI, the `call --calls` sequence, MCP JSON-RPC, the tool schema, and an in-process snapshot cache.
- Linux supports the same `ULTRATERM_COMPUTER_USE_ACTION_READ_BACK` setting as macOS. By default it keeps the wait after an action and returns the full snapshot. When set to `0`, `false`, `no` or `off` (case-insensitive, ignoring surrounding whitespace), a successful action returns only `ok`. It skips the read-back wait, AX, focus and selection, and screenshot capture. It also does not overwrite the index cache from the last explicit observation. The REPL adapter sets this switch automatically. Callers that need an observation should call `get_app_state` or `getAXState()` explicitly, and refresh indexes after the interface changes. `ok` only means that the action call completed. It does not mean the interface has finished updating or that the task succeeded. Explicit observation is not affected by the switch and still returns the full snapshot.
- The build entry point is `scripts/build-ultraterm-computer-use-linux.sh --arch arm64|amd64`. By default it writes to `dist/linux/<arch>/ultraterm-computer-use`. The npm release package bundles both Linux artifacts into the existing root and alias packages. The Node launcher selects one automatically based on `process.platform/process.arch`.
- The Go runtime embeds `runtime.py` through `go:embed`. When a tool call runs, it writes the script to disk temporarily and invokes `python3`. The Python bridge uses the AT-SPI2 interfaces exposed by GNOME/GObject Introspection for app and window discovery, accessibility tree rendering, semantic actions, editable text, value setting, and key and mouse synthesis, which is refused by default (see below).

  Text capability is detected through `Accessible.get_interfaces()` for `Text` / `EditableText`. It does not depend on convenience properties that may not exist in every PyGObject version.
- On Linux, the closest equivalent of macOS AX is AT-SPI2 / D-Bus accessibility, not a unified background keyboard and mouse input model. The first version prefers the AT-SPI actions, EditableText and Value interfaces that elements expose. Coordinate `click`, `drag` and key synthesis use the AT-SPI event synthesis, and they can disturb the person using the computer.

  Coordinate mouse synthesis moves the real pointer, so it is refused unless `ULTRATERM_COMPUTER_USE_ALLOW_GLOBAL_POINTER_FALLBACKS=1`. Key synthesis goes to whichever window has keyboard focus, so it is refused unless the target app window is active or the same switch is set. `type_text` first inserts at the caret of the focused editable field.

  Under Wayland, synthesis can only be treated as best-effort. Named keys are sent as keysyms with `KeySynthType.SYM`. Modifier keys are held with X modifier masks through `LOCKMODIFIERS` / `UNLOCKMODIFIERS`.

  `PRESS` / `RELEASE` / `PRESSRELEASE` accept only hardware keycodes, not keysyms.
- The Linux runtime must run inside the desktop session of the logged-in user. When `XDG_RUNTIME_DIR`, `DBUS_SESSION_BUS_ADDRESS` or the display environment is missing, the Go runtime tries to discover the current user's session bus and display or Wayland values before it starts the Python AT-SPI bridge. It looks under `/run/user/<uid>` and in common desktop processes. In a plain SSH tty where no logged-in desktop session can be found, the binary can still start, but it cannot inspect or operate the GUI session.
- The accessibility tree from `get_app_state` can be very deep on GTK and GNOME apps. The Linux bridge uses the same default tree budget as macOS and Windows: 1200 nodes and 64 levels. It also supports raising `max_tree_nodes` / `max_tree_depth` explicitly. The screenshot is captured best-effort through the GDK root window. On GNOME Wayland, the capture may return a black image. In that case the bridge detects an all-black sample and omits the image block.
- The focus summary and the selection share one lookup inside the window the snapshot has already chosen. Each is limited by `max_tree_nodes` / `max_tree_depth`. Once the depth boundary is reached, the lookup does not read the next level of children. If the lookup does not finish, an explicit note is appended. Selected text is read through the standard AT-SPI `get_n_selections` / `get_selection` interfaces. For the implementation and the isolated GTK verification, see [Linux bounded focus](linux-bounded-focus.md).
- For fields whose AT-SPI role is `password text`, the Text interface is not read. The snapshot's `value`, the tree row and `selectedText` contain none of its content. GTK 4's `GtkPasswordEntry` returns plain text from `GetText`. An ordinary GTK 4 `GtkEntry` with `visibility=false` reports the role `text`, so AT-SPI cannot identify it.
- `ULTRATERM_COMPUTER_USE_LINUX_LIGHTWEIGHT_HIDDEN=1` omits position, value and other details for nodes that are explicitly not SHOWING. The nodes, their indexes and their subtrees are kept. This is off by default. Unknown states are still read in full. For usage and real GTK verification, see [Linux hidden details](linux-hidden-details.md).
- The protocol surface of these 9 tools matches macOS and Windows: `list_apps`, `get_app_state`, `click`, `perform_secondary_action`, `scroll`, `drag`, `type_text`, `press_key`, `set_value`. Element-targeted actions preferentially reuse the runtime path metadata from the previous `get_app_state`. Coordinate actions use screenshot-relative or window-relative coordinates.
- `click_method=accessibility` on Linux maps to AT-SPI actions. `global` maps to AT-SPI mouse synthesis and requires the global pointer environment variable. AT-SPI has no equivalent of process-targeted mouse dispatch.

  Therefore `app_post` and the macOS-only `sky_click` return unsupported explicitly before snapshot lookup. `key_method=sky_key` does the same. `auto` prefers AT-SPI actions.

  If the element has no action, `auto` focuses the element through accessibility. It does not fall back to mouse synthesis unless the switch is set; without it the click is refused and nothing is sent. For GTK 3 text fields (`text`, `entry`, `password text`, `spin button`), the `activate` action is the Enter key ("Activates the entry").

  Running it submits the field instead of focusing it, so it is not treated as a click. `auto` focuses these fields through accessibility instead, and `accessibility` reports that they cannot be clicked. A plain Return on a focused GTK 3 text field runs its `activate` action without needing keyboard focus.

  The same-named action in GTK 4 is unchanged. On X11, GTK 4 has no usable pointer coordinates. For Gecko and Chromium, `activate` already focuses the element.
- Linux action read-back has its own GTK fixture. It can be retested through the native MCP server inside a private D-Bus and Xvfb session. For how to run it, see [Linux action read-back](linux-action-read-back.md). The Linux side is still a first functional version. It has no visual cursor overlay and no desktop entry. It also has no Linux fixture that covers all tools. Linux has an install script at `scripts/install.sh`.

## Background operation and state ids

- The runtime works in the background by default. It does not activate an app, raise or unminimize a window, move the real pointer or send keys to the front window unless a switch allows it. See [background operation](background-operation.md).

- Every state and action result carries a `state_id`. An action tool can pass it back. If the app was captured again in between, the action is refused with `stale_state` before anything is sent. See [state ids](state-id.md).

## Read-only commands, capture and structured errors (macOS)

These parts exist only in the macOS runtime. The Go runtimes for Linux and Windows do not have them.

- `targets [--running-only] [--json]`, `tools [name] [--json]` and `inspect [--window <title>] [--media-dir <path>] <app>` are read-only. `targets` and `inspect` resolve only running apps and never launch or activate one. `inspect` builds the snapshot with the read-only recovery policy, includes a screenshot (so it needs Screen Recording permission) and registers no state for later actions. With `--media-dir`, `externalizeToolResultImages` writes each base64 image into that directory as `<app>-inspect-<index>.<png|jpg|webp>` and replaces it with an `image_path` item that holds the file path.
- App targets accept `pid:<pid>` or a bare pid, which address exactly one process, besides names and bundle identifiers. A name that matches several apps is refused with `ambiguousApp` and its candidates. The password-manager safety denylist applies however the app is addressed (pid, bundle identifier or name), compares bundle identifiers case-insensitively, and discovery output never lists a blocked app or its pid.
- `preview` and `record` capture one window of an already running app through ScreenCaptureKit. They check `CGPreflightScreenCaptureAccess()` first and stop with a message that points to `doctor` when Screen Recording is not granted. They pick the largest titled on-screen layer-0 window of at least 64 by 64 points, resolved by name or bundle identifier. They never launch, activate or unhide the app, open no viewer, make no network call and write only where the caller points them. `preview` replaces `latest.jpg` atomically inside `--output-dir` and keeps `manifest.json` (status `capturing`, `completed`, `cancelled` or `failed`, plus counters). `record` writes one H.264 MP4 with no audio to `--output`. Limits: `preview` duration up to 3600 seconds; `record` duration cut to 600 seconds and output cut at 300 MB (a bitrate-derived deadline is a second bound); both 1 to 60 fps and widths of 64 to 16384 px; `record` bitrate 100000 to 200000000 bps. A partial recording is removed on failure. Both print a JSON summary, and SIGINT or SIGTERM ends the capture as `cancelled`.
- Structured errors: `computerUseErrorInfo(for:phase:callIndex:)` maps any failure to `{code, phase, call_index, retryable, hint, candidates, message}`. The result text stays the error's own description, and the object is added as an extra `error` key on error results, so existing text is unchanged. `ultraTermComputerUseExitStatus` maps codes to stable process statuses: 0 success, 1 other failure, 2 usage or invalid arguments, 3 permission denied, 4 app not found, 5 ambiguous app, 6 state unavailable, 7 stale state.
- `ToolSchemaValidator` checks `call` arguments against the tool input schemas before dispatch. A `call --calls` sequence is validated in full before its first call runs; an unknown tool name is skipped by the preflight and reported when the sequence reaches it.
- `click` validates its arguments: `mouse_button` must be one of the known buttons, `click_count` a positive whole number, and JSON booleans are rejected where a number or an element index is expected.
- The accessibility tree walk has a visit budget besides the render budget: by default at most 10,000 nodes visited and a walk depth of 256 (`AccessibilityTreeLimits.maxVisitedNodeCount` and `maxVisitedDepth`), counting nodes that are elided and never rendered. Accessibility messaging has a 4 second timeout, so a hung app cannot block a snapshot.
- The visual cursor writes its observation file only when the phase, tip position, resting position or rotation changed; the timestamp is ignored for that comparison.

## Key Boundaries

- The open-source version does not currently reproduce the caller signing, private IPC, full overlay choreography or plugin self-install logic of the official closed-source implementation.
- Because the official `SkyComputerUseClient` carries host-side launch constraints, a plain stdio MCP client on this machine may be killed directly by the system. If you probe the official bundled `computer-use`, the app-server mode of the probing helper is currently only suitable for observing the tool list and protocol surface. Real tool calls of the official `1.0.755` also go through service-side sender authorization and active IPC client tracking. An external raw helper, even one using a signed Codex binary, may return `Sender process is not authenticated`. To use the official tools for real, go through the normal Codex agent and tool call chain. The open-source version continues to provide the directly connectable `ultraterm-computer-use` MCP server.
- The current permission onboarding has a runnable app, deep links, a drag assist, and a version of the accessory panel entry animation and back affordance that is closer to the official one. The click path also has an independent visual cursor, an official asset fallback, and ordering relative to the target window. While the overlay is visible, it keeps reasserting that it is above the target window. This prevents the cursor from being covered again when the user manually activates the target app. Overall, it does not yet fully replicate the official embedded choreography, host integration or session approval experience.
- Screenshots currently capture the target window through `ScreenCaptureKit`. They are returned as an MCP `image` content block, as base64 PNG (default) or the configured JPG or WebP. Ordinary app screenshots are no longer written to the repository or a temporary directory. Before encoding, images are proportionally downscaled to the configured maximum long edge. Or they are omitted according to the over-limit policy and the minimum total pixel threshold. Coordinate tools continue to map coordinates using the actual returned screenshot pixel size. Each ScreenCaptureKit capture has a timeout. On timeout, the image block is omitted instead of blocking the whole `get_app_state`.
- Session state is now in-process memory. It stores the most recent snapshot and the element index mapping for each app.

## User Configuration

On macOS, screenshot reads the user's JSON configuration on each capture. Precedence is ENV > file > default. The npm launcher provides `ultraterm-computer-use config` to show, set, reset and print the path. It supports PNG, JPG and WebP, JPEG quality, the maximum long edge and downscale policy, a minimum total pixel threshold for dropping images, and the ScreenCaptureKit timeout. The hardware capture path remains the preferred path. The app agent forwards the resolved config path with each request and clears image environment variables that were not provided, so a resident value does not pollute later requests. See [Configuration](configuration.md).

The screenshot pixel drop threshold is computed as width × height. Images whose area is strictly below the threshold are not returned, but the AX data and the reason are kept. After a configuration omits the screenshot, coordinate input is rejected. Lossless WebP encoding is statically linked against a fixed libwebp version. The license text ships with the app and npm artifacts.

## Targeted AX Query

On macOS, `query` is added alongside the original 9 tools. It finds AX elements in the target window by text or role, without taking a screenshot or rendering the full tree. Windows and Linux keep the original 9 tools. A query resolves only running apps and uses a bounded BFS (500 nodes by default, at most 5000, with a 2-second cooperative traversal deadline). Results include the matches and completeness metadata. String and child pagination is also bounded. AX read errors mark the result as incomplete.

Query indexes belong to the current native session. At most 5000 are kept, and they expire after 120 seconds. They are cleaned up when the session ends and are never reused. Before any element action, the process identity, window ownership, query criteria and latest geometry are verified. If any check fails, the query must be run again. Old coordinates are not used. The JS call `cua.getApp(name, { initialState: false })` skips the initial snapshot, and `app.query()` returns structured results. See [Targeted query](targeted-query.md).

## Structured Permission Query

On macOS, `doctor --status-only` prints the same text summary as `doctor` but never launches onboarding and never starts the app agent. `doctor --json` reuses `PermissionDiagnostics` in both the CLI and app-agent proxy paths. It outputs a single JSON snapshot and does not open onboarding. The fields are `platform: "macos"`, `accessibilityTrusted`, `screenCaptureGranted`, `allGranted`, and `missingPermissions` (`accessibility` / `screenRecording`). Missing permissions still exit with status 0. Hosts should read `allGranted` and query again when authorization changes. This state follows the merged system API and TCC diagnostic semantics. It is not proof that an operation will succeed. Linux and Windows explicitly reject this permission query mode. Plain `doctor` keeps its text output and permission guidance.

Password field observation does not return the value or selection of a control marked as a password field. For how Linux and Windows identify them, the real fixtures and the known limits, see [Password fields](password-fields.md).

The macOS click chain stops when the result of an AX action is uncertain. It does not switch methods to resend. A partially successful multi-click is not resent as a group either. For reproduction and limits, see [Click outcomes](click-outcomes.md).

On Windows, dangerous TextPattern selection reads in Chromium and Electron are skipped before the call. Unknown windows and embedded Chromium also do not probe that selection. Ordinary native controls keep it. See [Windows selected text](windows-selected-text.md).

Linux session discovery excludes sandboxed processes and no longer imports `AT_SPI_BUS_ADDRESS` from other processes. An explicit caller value is kept. By default, the libatspi session bus query is used. See [Session discovery](linux-session-discovery.md).

On macOS, before input, a snapshot element action checks the original AX reference's role and subrole, name and identifier. Static text and pop-up buttons also check the value. An identity change, an invalid reference or a read failure requires re-observation. No same-named substitute is searched for. Ordinary input values and checked state are not used as identity. The value is read on demand, only after the current role and subrole are confirmed. Password fields do not have their value read. Real regression entry: `scripts/tests/macos-element-identity-smoke.mjs`.

Before clicking an element index or performing a secondary action on it, macOS re-reads `AXEnabled`. A clearly disabled ordinary control rejects input. Menu items keep the original behaviour, because a closed menu may expose a stale enabled state. Real AppKit regression entry: `scripts/tests/macos-disabled-control-smoke.mjs`.

## Main Verification Paths

- Unit tests: `swift test`
- JS REPL and CLI contract: `node --test scripts/node-repl/*.test.mjs`
- End-to-end smoke: `./scripts/run-tool-smoke-tests.sh` (the standard 9-tool smoke plus the visual cursor idle smoke. By default the script starts the internal fixture in headless mode, so no test windows open on the user's desktop)
- App packaging: `./scripts/build-ultraterm-computer-use-app.sh debug`
- Release-optimized dev-identity app: `ULTRATERM_COMPUTER_USE_APP_VARIANT=dev ./scripts/build-ultraterm-computer-use-app.sh release`. It keeps the dev bundle identifier and the `(Dev)` name. It can be used to measure release performance when the dev identity already has permissions and the signing identity matches. It does not inherit the official app's permissions. It does not delete the official or legacy bundles in the same output directory. Only `dev` is accepted. This variable applies only to direct app builds. npm, release packaging and the plugin install entry points reject it, so unset it before running those commands. This avoids selecting an older official package next to it. Real build regression: `python3 scripts/tests/macos-app-variant-smoke.py --signed`.
- Permission onboarding end-to-end regression: `./scripts/run-permission-onboarding-e2e.sh`. It requires that macOS has already granted Accessibility and Screen Recording to the `ultraterm-computer-use` under test. By default it disables the app-agent proxy to test the current CLI runtime state. You can set `ULTRATERM_COMPUTER_USE_E2E_CLI=/path/to/ultraterm-computer-use` to choose the CLI under test. You can set `ULTRATERM_COMPUTER_USE_E2E_DISABLE_APP_AGENT_PROXY=0` to override the default proxy behaviour explicitly.
- npm staging: `node ./scripts/npm/build-packages.mjs`
- Release tarball: `./scripts/release-package.sh`
- Skill packaging: `npm run package:skill`
